# План TsubameDo

Рабочий план. После каждого шага отмечаем сделанное здесь.

## Зачем

Три вещи, которые мешают в Insomnia, — это главные требования, и каждый этап их проверяет:

1. **Тяжёлый.** Цель: холодный запуск приложения меньше 1 с, в покое не больше 150 МБ памяти
   вместе с WebView, DMG меньше 15 МБ.
2. **Не открывает большие ответы.** Цель: JSON на 300 МБ открывается без зависания —
   прокрутка, поиск, сворачивание дерева, фильтр по JSONPath.
3. **Требует аккаунт.** Никаких аккаунтов, облака и телеметрии. Коллекции — файлы в git.

Как в прошлых программах: ядро на Rust, оболочка на Tauri (как Musubiko), сначала macOS,
потом Windows и Linux через CI. Без аккаунта Apple Developer: сборка без подписи, раздача
с сайта, на странице загрузки — как открыть неподписанное приложение.

Чем отличаемся от похожих программ: Yaak (тоже Tauri и Rust), Bruno (тоже файлы в git),
Postman. У нас — точечное сохранение файлов без лишнего диффа, большие ответы как
сильная сторона, CLI из того же ядра для CI и сравнение ответов.

## Этап 0. Ядро и CLI — сделано

- [x] Отправка запроса со своим соединением: время DNS, подключения, TLS, ожидания и загрузки.
- [x] HTTP/1.1 и HTTP/2 (ALPN), TLS на rustls с системными сертификатами (видит корпоративные
      CA), отключение проверки для тестовых стендов.
- [x] Перенаправления как в браузере (303 и POST после 301/302 становятся GET, авторизация не
      уходит на другой сервер), лимит 10.
- [x] gzip, deflate, brotli; размер по сети и после распаковки.
- [x] Большие ответы: тело больше 8 МБ пишется во временный файл, который удаляется вместе
      с ответом. 263 МБ — 0,24 с и 30 МБ памяти.
- [x] Модель запроса: параметры, заголовки (выключенные остаются в файле), Basic, Bearer,
      API key, тело JSON, текст, form, multipart с файлами, файл целиком.
- [x] Файл запроса в TOML через `toml_edit`: сохранение без изменений ничего не переписывает,
      правка меняет только свою строку. YAML не подошёл: в Rust нет редактора YAML, который
      сохраняет оформление.
- [x] Коллекция: папка, окружения, секреты в `*.local.toml`, переменные с вложенными ссылками,
      встроенные `$uuid`, `$timestamp`, `$env.ИМЯ`; понятная ошибка со списком всех
      незаданных переменных.
- [x] CLI: `send`, `run`, `check`, `init`. Сообщения на русском.

## Этап 1. Приложение — минимальная версия

- [ ] Каркас Tauri 2 в `apps/desktop` (React + TS, как Musubiko), мост к ядру через команды.
- [ ] Окно: коллекции и папки слева, запрос посередине, ответ справа; несколько вкладок.
- [ ] Редактор запроса: метод, адрес с подсветкой `{{переменных}}` и подсказками, параметры,
      заголовки, авторизация, тело (CodeMirror 6), сохранение через `RequestFile::update`.
- [ ] Окружения: переключатель, редактор переменных, секреты в отдельном файле.
- [ ] Ответ: статус, время по фазам (полоска как в DevTools), размер, заголовки, cookies.
- [ ] **Просмотр больших ответов** — главное отличие, делаем сразу:
  - [ ] тело читается из файла кусками, интерфейс получает только видимые строки;
  - [ ] индекс строк и структуры JSON в ядре (как в CommaEditor), сворачивание дерева;
  - [ ] поиск по ответу в ядре, на всех ядрах процессора;
  - [ ] форматирование JSON в фоне, без копии всего ответа в WebView.
- [ ] История отправленных запросов (локально, с ограничением по размеру).
- [ ] Отмена запроса, ⌘Enter — отправить, ⌘K — палитра.
- [ ] Импорт из curl и «Скопировать как curl».
- [ ] Замеры: время запуска и память в покое, сравнение с Insomnia на одном ответе.

## Этап 2. Цепочки и проверки

- [ ] Значение из ответа другого запроса: `{{response.login.body.$.token}}`, с отправкой
      зависимого запроса при необходимости.
- [ ] Проверки ответа: статус, время, JSONPath, JSON Schema; результаты в приложении и в CLI.
- [ ] Скрипты до и после запроса на JS (QuickJS в ядре — работают и в CLI).
- [ ] `tsubamedo run`: отчёт JUnit для CI, параллельный запуск, повтор упавших.
