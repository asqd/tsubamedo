# План TsubameDo

Рабочий план. После каждого шага отмечаем сделанное здесь.

## Зачем

Три вещи, которые мешают в Insomnia, — это главные требования, и каждый этап их проверяет:

1. **Тяжёлый.** Цель: холодный запуск приложения меньше 1 с, в покое не больше 150 МБ памяти
   вместе с WebView, DMG меньше 15 МБ.
2. **Не открывает большие ответы.** Цель: JSON на 300 МБ открывается без зависания —
   прокрутка, поиск, сворачивание дерева, фильтр по JSONPath.
3. **Требует аккаунт.** Никаких аккаунтов, облака и телеметрии. Коллекции — файлы в git.

Как в прошлых программах: ядро на Rust, оболочка на Tauri (как Musubiko), сначала macOS,
потом Windows и Linux через CI. Без аккаунта Apple Developer: сборка без подписи, раздача
с сайта, на странице загрузки — как открыть неподписанное приложение.

Чем отличаемся от похожих программ: Yaak (тоже Tauri и Rust), Bruno (тоже файлы в git),
Postman. У нас — точечное сохранение файлов без лишнего диффа, большие ответы как
сильная сторона, CLI из того же ядра для CI и сравнение ответов.

## Этап 0. Ядро и CLI — сделано

- [x] Отправка запроса со своим соединением: время DNS, подключения, TLS, ожидания и загрузки.

- [x] Перенаправления как в браузере (303 и POST после 301/302 становятся GET, авторизация не

- [x] gzip, deflate, brotli; размер по сети и после распаковки.
- [x] Большие ответы: тело больше 8 МБ пишется во временный файл, который удаляется вместе

- [x] Модель запроса: параметры, заголовки (выключенные остаются в файле), Basic, Bearer,

- [x] Коллекция: папка, окружения, секреты в `*.local.toml`, переменные с вложенными ссылками,

      незаданных переменных.
- [x] CLI: `send`, `run`, `check`, `init`. Сообщения на русском.

## Этап 1. Приложение — минимальная версия

Замеры собранного приложения (TsubameDo.app 0.1, MacBook разработчика). Память — как в
колонке «Память» Мониторинга системы (`footprint`), по всем процессам приложения. Сумма RSS
больше, но она по разу считает в каждом процессе общие библиотеки WebKit, которые система
держит один раз.

| Что | Цель | Сейчас |
|---|---|---|
| Окно после запуска | < 1 с | 0,88 с |
| Память в покое, вместе с процессами WebView | ≤ 150 МБ | 111 МБ после запуска (приложение 22, WebContent 55, GPU 28, сеть 6); 128 МБ после закрытия вкладки с ответом на 263 МБ |
| Размер приложения | DMG < 15 МБ | 9,2 МБ (Apple Silicon) и 9,8 МБ (Intel), 0.1.0 с этапами 2–4; универсальный был бы 18 МБ |
| JSON 263 МБ: красивый вид | без зависания | 0,2 с на форматирование на 10 ядрах (было 1,4 с в одном потоке), затем 28 млн строк листаются сразу |
| Память с этим ответом | — | 264 МБ всего, приложение 167 (индекс строк 56 и свёртки 32) |
| Поиск по нему без учёта регистра | — | меньше секунды до первого совпадения, считает до 1 млн |

      живут в `core/tsubamedo-session` за одним вызовом `call`: и приложение, и мост для
      браузера (`make bridge`) пересылают в него, поэтому расходиться им не в чем.
- [x] Окно: коллекция слева, запрос посередине, ответ справа, разделитель тянется.
- [x] Редактор запроса: метод, адрес, параметры, заголовки, авторизация, тело (JSON, текст,
      форма, multipart, файл), настройки. Правки сразу сохраняются в файл через
      `RequestFile::update` — меняется только своя строка (проверено на живом файле).
- [x] Окружения: переключатель в верхней панели, выбор запоминается для коллекции.
- [x] Черновик без коллекции — как адресная строка, хранится только в окне.

- [x] **Просмотр больших ответов:**
  - [x] ядро держит текст (как есть или JSON с отступами во временном файле) и индекс строк —
        начало каждой 1024-й; окно просит только видимые строки;
  - [x] своя прокрутка и полоса — браузер не прокручивает 28 млн строк;
  - [x] сворачивание объектов и массивов, «Свернуть» верхний уровень (до 100 000 объектов);
  - [x] поиск в ядре по всему виду, без учёта регистра и для кириллицы, переход по совпадениям;
  - [x] подсветка JSON только для видимых строк; «Копировать» до 20 МБ, «Сохранить…» любого размера.
- [x] Отмена запроса, ⌘↵ — отправить, ⌘O — открыть коллекцию, ⌘N — новый запрос, ⌘F — поиск в ответе.
- [x] Иконка: ласточка (`design/make-icon.swift`).
- [x] Память в покое: 111 МБ после запуска. Прежние 157 МБ были суммой RSS — в ней общие
      библиотеки WebKit посчитаны в каждом процессе. Ядро держит тело и виды ответа, пока

      приложение вернулось со 176 до 36 МБ, свободное ядро отдаёт системе
      (`malloc_zone_pressure_relief`). Раньше держались последние 30 ответов.
- [x] Вкладки: несколько открытых запросов, у каждого свой ответ и своя отправка; черновиков

      место следующей — просмотр списка не плодит вкладки. Открытые вкладки запоминаются для
      каждой коллекции. ⌘T, ⌘W, ⌘1…⌘9, ⌃Tab, ⌘⇧[ и ⌘⇧]; средняя кнопка мыши закрывает.
      Меню macOS своё, без «Закрыть окно», поэтому ⌘W закрывает вкладку (проверено в приложении).
- [x] CodeMirror 6 для адреса, значений параметров, заголовков, полей авторизации и тела:
      JSON с подсветкой, сворачиванием, парными скобками и поиском (⌘F).
- [x] `{{Переменные}}`: заданные подсвечены, незаданные — красным с волнистой линией и списком
      под адресом ещё до отправки (с учётом вложенных: `base` → `{{host}}`). При наведении —
      значение и откуда оно (секреты из `*.local.toml` скрыты). После `{{` — подсказки:
      переменные окружения и встроенные.
- [x] Импорт из curl: команда, вставленная в адрес, становится запросом — параметры,
      заголовки, Bearer и Basic во вкладку авторизации, JSON, форма, multipart, файл, `-G`,
      `-k`, `$'…'` из «Copy as cURL» браузеров. «Вернуть как было» — в подсказке после вставки.
- [x] «Скопировать как curl» с подставленными переменными; проверено настоящим curl.
- [x] История отправленных запросов: в папке данных приложения (`~/Library/Application
      Support/app.tsubamedo.TsubameDo`), а не в коллекции, чтобы не попасть в git. Запрос
      хранится как написан, с `{{переменными}}`; значения Authorization, Cookie и заголовков
      с key/token/secret в «Отправлено» скрыты. Тела ответов до 1 МБ хранятся как пришли (если
      сервер вернул токен в теле, он там будет). 500 записей на коллекцию, группы по дням,
      фильтр «только этот запрос», очистка. Запись открывается вкладкой-черновиком с ответом.
      Неотправленные (незаданная переменная) не пишутся, сетевые ошибки — пишутся.
- [x] Боковая панель — дерево папок, как на диске, включая пустые. Правый клик или «⋯»:
      переименовать (имя = имя файла, недопустимые символы заменяются), дублировать,
      переместить в…, удалить в Корзину с подтверждением; для папок — новый запрос и папка
      внутри. Перетаскивание запросов и папок. Двойной щелчок — переименовать, новые запрос
      и папка сразу ждут имя. Открытые вкладки и история переезжают вслед за файлами.
- [x] Форматирование больших JSON на всех ядрах: тело режется на части сразу после запятых
      вне строк, части форматируются параллельно в свои файлы, индекс строк и свёртки
      сшиваются. 263 МБ — 0,2 с вместо 1,4 с, результат совпадает с `jq .` байт в байт.
      Хода форматирования в окне не нужно. Вложенность глубже 1000 уровней показывается как
      есть: отступы в ней занимали бы больше, чем сам ответ.
- [x] Индекс строк без 2 байт на строку: только начало каждой 1024-й строки и пометка блоков,
      где длинная строка резалась; строка внутри блока — подсчётом `\n` (в блоках без резки —
      пачками, которые компилятор векторизует). JSON 263 МБ (26 млн строк): пик памяти 875 → 817
      МБ; экран из 100 строк — 0,1 мс; поиск — 55–65 мс, как было (номера строк считаются только
      для первых 100 000 строк с совпадениями). Совпадение с прежней резкой проверено на случайных
      данных с длинными строками, кириллицей на границе и `\n` ровно на ней.
- [x] Сравнение с Insomnia 13.3.1 на том же ответе (JSON 263 МБ с локального сервера), память —
      `footprint` всех процессов вместе: приложение 22 МБ против 1,1 ГБ; окно через 0,7 с против
      1,8 с; в покое 248 против 852 МБ (Insomnia — с рабочими коллекциями); ответ — 0,2 с и сразу
      красиво, с поиском, против 0,6 с и «Responses over 100MB cannot be shown»; с ответом 316–330
      против ~870 МБ. Таблица — в README. В покое сегодня 248 МБ, а не 111, как в замере выше:
      процесс GPU WebKit занял 147 МБ вместо 28 — надо разобраться, прежде чем выносить на сайт.

## Этап 2. Цепочки и проверки

- [x] Значения из ответа: `[capture] token = '$.token'` в файле запроса, другие запросы пишут
      просто `{{token}}`. Если значения нет, запрос, который его даёт, отправляется сам первым
      (цепочкой, до 8 шагов, упавший не повторяется). Значения хранятся в папке данных
      приложения для каждого окружения и переживают перезапуск; «Очистить историю» удаляет и их.
      Сильнее файлов коллекции, слабее `--var`. Синтаксис `{{response.login.body.$.token}}`
      из первого плана не понадобился: имя переменной читается лучше и подсвечивается.
- [x] Проверки ответа строками в `checks = [...]`: `status`, `time`, `size`, `header Имя`,
      `body`, JSONPath (RFC 9535 через `serde_json_path`) и `count`; условия `==`, `!=`, `<`,
      `>`, `contains`, `matches`, `exists`, `empty` и `not`. В приложении — вкладка «Проверки»
      у запроса (строка проверяется ядром прямо при вводе) и у ответа (что пришло); в CLI —
      ✓/✗ под ответом и код выхода. Строки, которые не менялись, сохраняют своё оформление.
- [x] Пути с несколькими совпадениями (`[*]`, `..`, фильтры, срезы): сравнения и `matches`
      проверяют каждое совпадение и называют не подошедшие с местом, `count`/`exists`/`empty`/
      `contains` смотрят на список, `count` — число совпадений. Пустой результат — провал.
- [x] JSON Schema в проверках: `$ schema schemas/order.json`, `$.items[*] schema {…}` (boon,
      draft 4 — 2020-12, без сети); нарушения по-русски с путём. Импорт OpenAPI пишет схемы
      ответов в `schemas/` и добавляет такую проверку.
- [x] Скрипты до и после запроса на JS: QuickJS (`rquickjs`) в ядре, работают и в CLI. До
      запроса — запрос как в файле, его можно менять, `vars.set` подставляется в этот же
      запрос; после — `response`, `test`/`expect`, `vars.set` для других запросов (такой запрос
      тоже отправляется сам, если значения нет). `console.log` — в журнал под ответом и в CLI;
      `crypto.sha*/hmac` (через ring), `btoa`/`atob`. Песочница без файлов, сети и модулей,
      5 с и 256 МБ на скрипт. Приложение выросло с 16,3 до 18,0 МБ (вместе с JSONPath),
      память в покое не изменилась (103 МБ).
- [x] `tsubamedo run`: проверки, порядок по зависимостям (`--filter` подтягивает нужные
      запросы из других папок), отчёт `--junit report.xml`. В приложении — ▶ для всей
      коллекции и «Запустить папку»; результаты поверх редактора, щелчок открывает запрос.
- [x] Параллельный запуск и повтор упавших: `run -p 4 --retry 2`; запрос ждёт только тех,
      чьи значения берёт. Повторяется лишь то, что ушло на сервер (не «нет переменной»),
      с паузой 0,5 с × попытка. Упавший источник значения не отправляется заново перед каждым
      зависимым запросом.
- [x] Ход запуска в окне: план сразу, строки оживают по мере ответов (окно опрашивает ядро
      раз в 250 мс), «одновременно» и «повторы» в панели, «Повторить упавшие» — только их.

## Этап 3. Импорт и протоколы

- [x] Импорт: Insomnia (v4 JSON, v5 YAML), Postman (коллекции v2.0/2.1, окружения,

- [x] Все случайные переменные Postman (`fake.rs`, около 130: `$randomEmail`, `$randomPrice`,
      картинки по темам…) — на маленьких словарях; тег `{% faker %}` Insomnia — в них же.
- [x] `pm.cookies` и `cookies` в скриптах: банка окружения для адреса запроса (после ответа — с

- [x] Внешние `$ref` в OpenAPI (`import/bundle.rs`): описание из нескольких файлов собирается

Протоколы (GraphQL, WebSocket и SSE, gRPC) отложены: нужны реже, чем этап 4, — см. «Потом».

## Этап 4. Продвинутое

- [x] Cookie jar на окружение (`cookies.rs`, RFC 6265, свой разбор без зависимостей): домен и
      путь, Secure только по HTTPS и на этот компьютер, Max-Age и Expires, удаление сервером,
      cookie на каждом шаге перенаправлений. Свои cookie из заголовка сильнее банки. Банка —
      в папке данных приложения у каждого окружения своя, в CLI — на одну команду
      (`--no-cookies`), у запроса — `[options] cookies = false`. Окно «Cookie»: список,
      удалить одну или все.
- [x] OAuth 2.0 (`oauth.rs`): authorization code с PKCE (S256, код ловится на
      `127.0.0.1:<порт>` по RFC 8252, `state` проверяется, 5 минут на вход, отмена), client
      credentials, password. Токен хранится по настройкам (ключ — SHA-256, секреты не лежат
      рядом с токеном), берётся из хранилища, пока не истёк, обновляется по refresh token;
      на 401 с сохранённым — новый токен и повтор. Параллельные запросы ждут один вход. В окне —
      поля, срок токена, «Получить новый», «Забыть»; заметки — в «Журнале» ответа.
- [x] Прокси (`http/proxy.rs`): системный — `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY`/`NO_PROXY`,
      иначе настройки macOS (`scutil --proxy`, перечитываются раз в 10 с); свой или без прокси.
      HTTP-прокси: HTTPS через `CONNECT`, HTTP в абсолютной форме, логин из адреса; SOCKS5 с
      логином, имя разрешает прокси. Исключения: домены с поддоменами, сети `10.0.0.0/8` и
      маковские `169.254/16`, `host:порт`, простые имена. localhost всегда напрямую. PAC не
      выполняется (окно об этом говорит). В приложении — «Настройки», в CLI — `-x`, `--noproxy`.
- [x] Клиентские сертификаты (`http/client_cert.rs`): `[[certificates]]` в `tsubamedo.toml` по
      хосту (`*.bank.test`, `host:8443`), пути и пароль с `{{переменными}}`. PEM разбирается
      сам; .p12/.pfx и зашифрованные ключи — системным `openssl` (PKCS#12 на Rust тянул 56
      пакетов). Прочитанное кешируется, пока файлы не менялись. В окне — список с проверкой
      каждого, в ответе — какой сертификат ушёл; в CLI — `-E/--cert`, `--key`, `--pass`. Если
      сервер оборвал TLS без сертификата — подсказка, что он, возможно, его ждёт.
- [x] Digest (`digest.rs`, RFC 7616 и 2069): MD5 (своя, без пакета), SHA-256, `-sess`, qop auth
      и auth-int; ответ на вызов из 401 и повтор. Импорт из Postman и Insomnia, curl `--digest`.
- [x] AWS Signature v4 (`sigv4.rs`, HMAC и SHA-256 из ring): подпись в момент отправки и при
      каждом повторе; путь и параметры переписываются в кодировку AWS, так что ушло то, что
      подписано; S3 — хеш тела, один раз закодированный путь; токен сессии. Совпадает с
      примерами AWS (get-vanilla, IAM) и с `curl --aws-sigv4`. Импорт из Postman (`awsv4`),
      Insomnia (`iam`) и curl; в коде — `curl --aws-sigv4`, в остальных языках — пометка.
      Этап 4 закрыт.
- [x] Сравнение двух ответов (`compare.rs`): статус; заголовки без тех, что меняются всегда
      (Date, X-Request-Id, трассировка; «все заголовки» показывает и их); JSON по смыслу — путь
      каждого изменения, массивы объектов с уникальным `id` сопоставляются по нему (вставка —
      одно изменение, перестановка — одно «порядок»), «не сравнивать» по пути, `[*]` или имени
      поля; текст построчно (`similar`, patience, 2 с на diff); больше 32 МБ (JSON) и 8 МБ
      (текст) — с какой строки расходятся, потоком. В окне «Сравнить…» у ответа: с другим
      окружением (запрос уходит туда же) или с прошлым ответом из истории; ⊘ у изменения
      добавляет его путь в «не сравнивать», список запоминается для запроса. CLI:
      `tsubamedo compare запрос -e stage --with prod --ignore requestId`, код 1 при различиях.
- [x] Генерация кода (`codegen/`), набор как у Insomnia (httpsnippet): Shell — curl, HTTPie,
      wget; PowerShell; Python — requests, http.client; JavaScript — fetch, axios,
      XMLHttpRequest; Node.js — fetch, axios, http; Go; Java — HttpClient, OkHttp; Kotlin
      (OkHttp); C# (HttpClient); PHP — cURL, Guzzle; Ruby; Swift; Rust (reqwest); Dart; C
      (libcurl); сырой HTTP/1.1. JSON для requests — словарём, для JavaScript — объектом;
      формы — парами; файлы multipart и тела — по путям (`prepare_without_files`: для кода
      файлы не читаются). Чего библиотека не повторит (Digest, выключенная проверка
      сертификата, без перенаправлений, multipart в низкоуровневых клиентах), сказано
      комментарием в начале кода. Строки экранируются по правилам языка (`$` в Kotlin и Dart,
      `\u{…}` в Swift и Rust, восьмеричные в C). Незаданные переменные — `<имя>`, кроме адреса.
      Сгенерированный код запускается по-настоящему: `cargo test -p tsubamedo-core --test
      codegen -- --ignored` — curl, Python, Node, Go, Ruby, Swift и C против эхо-сервера, 29
      прогонов. В окне — «Код…» у запроса; в CLI — `tsubamedo code запрос -l go`.

## Этап 5. Работа в команде без облака

- [x] Git (`git.rs`) через системный `git` — ключи, настройки и хранилище паролей
      пользователя, без своей копии git и без запросов пароля (`GIT_TERMINAL_PROMPT=0`, ограничение
      по времени). Статус (`--porcelain=v2 -z`): буквы у запросов и точки у папок в дереве, вкладка
      Git — ветка, ↑/↓ после `fetch`, изменения с отметками, diff файла. Коммит только выбранных
      файлов (что ещё было в индексе — не трогается), `*.local.toml` не коммитятся и одной
      кнопкой уходят в `.gitignore`. «Получить» — `pull --rebase --autostash`; при конфликте
      rebase отменяется, репозиторий как был, названы файлы. «Отправить» — новая ветка в origin с
      привязкой. Коллекция в подпапке репозитория — только её файлы. Операции, меняющие
      репозиторий, идут по одной. «Создать репозиторий» для папки без git. Тесты — на настоящих
      репозиториях: сервер и два клона, конфликт, переименование, новая ветка.
