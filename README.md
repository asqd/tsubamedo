# TsubameDo

HTTP-клиент для работы с API, как Insomnia, но:

- **лёгкий** — ядро на Rust, интерфейс на Tauri вместо Electron: в покое около 110 МБ
  вместе с процессами WebView;
- **не боится больших ответов** — тело больше 8 МБ сразу уходит во временный файл:
  ответ на 263 МБ скачивается за 0,24 с и занимает 30 МБ памяти;
- **без аккаунта и облака** — коллекции лежат обычными файлами рядом с кодом и живут в git.

Есть приложение для macOS (Tauri) и CLI `tsubamedo` на одном ядре. JSON на 263 МБ
приложение форматирует на всех ядрах за 0,2 с и открывает с отступами, сворачиванием и
поиском — 28 млн строк листаются сразу.
План и замеры — в [docs/PLAN.md](docs/PLAN.md).

## Сборка

Нужен Rust 1.95 или новее.

Для приложения ещё Node 22 (`nvm use`).

```bash
make test      # тесты ядра
make check     # тесты, clippy и проверка типов интерфейса
make dev       # приложение с горячей перезагрузкой интерфейса
make run       # собрать TsubameDo.app (без подписи) и открыть
make bridge    # интерфейс в браузере на настоящем ядре: http://localhost:1430/bridge.html
make cli       # target/release/tsubamedo
make install   # tsubamedo в ~/.cargo/bin
make icon      # перерисовать иконку из design/make-icon.swift
```

## Устройство

- `core/tsubamedo-core` — всё про запросы: модель, файлы, переменные, отправка, просмотр тела.
- `core/tsubamedo-session` — команды окна за одним вызовом `call`; ими пользуются и приложение,
  и мост для браузера.
- `core/tsubamedo-cli` — `tsubamedo`.
- `apps/desktop` — интерфейс (React + TS), `src-tauri` — оболочка, `bridge` — мост для разработки.

## Коллекция

Коллекция — это папка:

```text
my-api/
  tsubamedo.toml          название и [vars] для всех окружений
  tsubamedo.local.toml    секреты коллекции, в git не попадают
  env/stage.toml          [vars] окружения stage
  env/stage.local.toml    его секреты
  orders/01-create.toml   запросы: папки группируют, имена задают порядок
```

Один запрос — один файл:

```toml
name = "Создать заказ"
method = "POST"
url = "{{base_url}}/orders"

[headers]
Accept = "application/json"
X-Debug = { value = "1", enabled = false }   # выключен, но не потерян

[auth]
type = "bearer"
token = "{{token}}"

[body]
type = "json"
content = '''
{"tour_id": {{tour_id}}, "request_id": "{{$uuid}}"}
'''
```

Когда приложение сохраняет запрос, оно меняет только те строки, которые вы правили:
комментарии, порядок и оформление остаются, а в git видна ровно ваша правка.

### Проверки и значения из ответа

```toml
name = "Вход"
method = "POST"
url = "{{base_url}}/login"
checks = [
  'status == 200',
  '$.token exists',
]

[capture]
token = '$.token'          # другие запросы пишут просто {{token}}
```

Запрос, которому нужен `{{token}}`, а его ещё нет, сначала сам отправляет «Вход». При запуске
коллекции такие запросы идут первыми, даже если они в другой папке. Полученные значения
приложение помнит между запусками (в папке данных, не в коллекции).

Что проверять: `status`, `time` (мс), `size`, `header Имя`, `body` или JSONPath `$.путь`
(RFC 9535, с фильтрами `$.items[?@.price > 100]`); после него `count` — длина массива, строки
или число совпадений. Условия: `==`, `!=`, `<`, `<=`, `>`, `>=`, `contains`, `matches`
(регулярное выражение), `exists`, `empty`, перед словами — `not`. Значение — JSON (`200`,
`"Кот"`, `true`, `[1, 2]`) или просто текст; `{{переменные}}` работают:

```text
status == 201
time < 500
header Content-Type contains json
$.items count > 0
$.user.name == "Котик"
$.id == {{order_id}}
$.error not exists
```

### Скрипты

Когда строк проверок мало — JavaScript до и после запроса. Он выполняется в ядре (QuickJS),
поэтому одинаково работает в приложении и в `tsubamedo run`:

```toml
[scripts]
before = '''
vars.set("ts", Date.now());          // {{ts}} подставится в этот же запрос
request.headers.set("X-Sign", crypto.hmac("sha256", vars.get("secret"), vars.render(request.body)));
'''
after = '''
const order = response.json();
vars.set("order_id", order.id);      // как [capture]: другие запросы отправят этот сами
test("заказ оплачен", () => expect(order.status).toBe("paid"));
console.log("товаров", order.items.length);
'''
```

- `vars` — `get`, `set`, `has`, `render(текст)`.
- `request` — `method`, `url`, `headers` и `query` (`get`, `set`, `has`, `remove`, `all`), `body`
  (текст JSON или просто текст; можно присвоить объект). До запроса — как в файле, с
  `{{переменными}}`, и его можно менять; после — то, что ушло, только для чтения.
- `response` (после) — `status`, `statusText`, `time`, `size`, `headers`, `text()`, `json()`.
- `test(имя, () => …)` и `expect(x)`: `toBe`, `toEqual`, `toContain`, `toMatch`, `toHaveLength`,
  `toHaveProperty`, `toBeGreaterThan`, `toBeLessThan`, `toBeTruthy`, `toBeDefined`… и `.not`.
  Тесты стоят рядом с проверками, в отчёте JUnit тоже.
- `console.log` — в журнал под ответом и в вывод CLI; `crypto.sha1/sha256/sha512/hmac`
  (hex или base64), `crypto.randomUUID()`, `btoa`/`atob` (строки UTF-8).

Песочница: без файлов, сети, модулей и таймеров; 5 секунд и 256 МБ на скрипт. Ошибка в
скрипте до запроса останавливает запрос, после — считается упавшей проверкой; строка ошибки
указана.

Переменные подставляются в порядке силы: коллекция → её `.local` → окружение → его `.local` →
значения из ответов и скриптов → `--var` из командной строки. Встроенные: `{{$uuid}}`, `{{$timestamp}}`, `{{$timestampMs}}`,
`{{$randomInt}}`, `{{$env.ИМЯ}}` (переменная окружения процесса — удобно для секретов в CI).

## Приложение

- Вкладки: ⌘T — черновик, ⌘W — закрыть, ⌘1…⌘9 — перейти, ⌘N — новый запрос в коллекции.
- `{{переменные}}` подсвечиваются везде, где их можно написать: незаданные — красным,
  при наведении видно значение и файл, откуда оно взято. После `{{` появляются подсказки.
- Команду curl (например, «Copy as cURL» из браузера) можно просто вставить в адрес — она
  станет запросом. Обратно — «Скопировать как curl».
- ⌘↵ — отправить, ⌘F — поиск в ответе или в теле запроса.
- Боковая панель повторяет папку коллекции: правый клик — переименовать, дублировать,
  перенести, удалить (в Корзину); запросы и папки можно перетаскивать.
- «История» в боковой панели: всё отправленное, с ответами до 1 МБ. Хранится в
  `~/Library/Application Support/app.tsubamedo.TsubameDo`, в git не попадает.
- Вкладка «Проверки» у запроса: проверки ответа (непонятная строка помечается сразу) и
  значения из ответа. У ответа — что прошло, что нет и что пришло вместо ожидаемого.
- Вкладка «Скрипты»: JavaScript до запроса и после ответа, с подсветкой и подсказками
  `vars.`, `request.`, `response.`, `expect(…).`.
- ▶ в боковой панели запускает всю коллекцию, «Запустить папку» в меню папки — одну папку.

## CLI

```bash
tsubamedo init my-api                         # новая коллекция с примером
tsubamedo send https://httpbin.org/get -i     # адрес, как curl
tsubamedo send orders/01-create -e stage      # запрос коллекции по имени
tsubamedo send orders/01-create.toml --var token=abc
tsubamedo send https://example.com/big.json -o big.json
tsubamedo run -e stage --fail                 # вся коллекция, код выхода для CI
tsubamedo run -e stage --junit report.xml     # и отчёт JUnit XML для GitLab, Jenkins, GitHub
tsubamedo run --filter orders --var token=$T  # только заказы; токен дан — вход не нужен
tsubamedo check                               # все ли переменные заданы во всех окружениях
```

`send` пишет статус и время по фазам (DNS, подключение, TLS, ожидание, загрузка) в stderr,
а тело — в stdout, поэтому его можно сразу передать в `jq`. В терминале JSON форматируется.
Для тестовых стендов с самоподписанным сертификатом есть `-k`.

`run` отправляет запросы по порядку файлов, но каждый — после тех, чьи значения он берёт.
Запрос считается упавшим, если ответа нет, не прошла проверка или не нашлось значение для
`[capture]`; с `--fail` — ещё и при статусе 400 и выше. `send` тоже выполняет проверки и
возвращает код 1, если какая-то не прошла.
