# TsubameDo

HTTP-клиент для работы с API, как Insomnia, но:

- **лёгкий** — ядро на Rust, интерфейс на Tauri вместо Electron: в покое около 110 МБ
  вместе с процессами WebView;
- **не боится больших ответов** — тело больше 8 МБ сразу уходит во временный файл:
  ответ на 263 МБ скачивается за 0,24 с и занимает 30 МБ памяти;
- **без аккаунта и облака** — коллекции лежат обычными файлами рядом с кодом и живут в git.

Есть приложение для macOS (Tauri) и CLI `tsubamedo` на одном ядре. JSON на 263 МБ
приложение форматирует на всех ядрах за 0,2 с и открывает с отступами, сворачиванием и
поиском — 28 млн строк листаются сразу.
План и замеры — в [docs/PLAN.md](docs/PLAN.md).

## Сборка

Нужен Rust 1.95 или новее.

Для приложения ещё Node 22 (`nvm use`).

```bash
make test      # тесты ядра
make check     # тесты, clippy и проверка типов интерфейса
make dev       # приложение с горячей перезагрузкой интерфейса
make run       # собрать TsubameDo.app (без подписи) и открыть
make bridge    # интерфейс в браузере на настоящем ядре: http://localhost:1430/bridge.html
make cli       # target/release/tsubamedo
make install   # tsubamedo в ~/.cargo/bin
make icon      # перерисовать иконку из design/make-icon.swift
```

## Устройство

- `core/tsubamedo-core` — всё про запросы: модель, файлы, переменные, отправка, просмотр тела.
- `core/tsubamedo-session` — команды окна за одним вызовом `call`; ими пользуются и приложение,
  и мост для браузера.
- `core/tsubamedo-cli` — `tsubamedo`.
- `apps/desktop` — интерфейс (React + TS), `src-tauri` — оболочка, `bridge` — мост для разработки.

## Коллекция

Коллекция — это папка:

```text
my-api/
  tsubamedo.toml          название и [vars] для всех окружений
  tsubamedo.local.toml    секреты коллекции, в git не попадают
  env/stage.toml          [vars] окружения stage
  env/stage.local.toml    его секреты
  orders/01-create.toml   запросы: папки группируют, имена задают порядок
```

Один запрос — один файл:

```toml
name = "Создать заказ"
method = "POST"
url = "{{base_url}}/orders"

[headers]
Accept = "application/json"
X-Debug = { value = "1", enabled = false }   # выключен, но не потерян

[auth]
type = "bearer"
token = "{{token}}"

[body]
type = "json"
content = '''
{"tour_id": {{tour_id}}, "request_id": "{{$uuid}}"}
'''
```

Когда приложение сохраняет запрос, оно меняет только те строки, которые вы правили:
комментарии, порядок и оформление остаются, а в git видна ровно ваша правка.

### OAuth 2.0 и cookie

Токен OAuth 2.0 приложение получает само перед отправкой, держит, пока он не истёк, и
обновляет по refresh token. Если сервер ответил 401 на сохранённый токен, запрос уходит ещё
раз с новым:

```toml
[auth]
type = "oauth2"
grant = "client_credentials"      # или password; без grant — вход в браузере
token_url = "{{auth}}/oauth/token"
client_id = "{{client_id}}"
client_secret = "{{client_secret}}"
scope = "orders:read"
```

Вход в браузере (authorization code) идёт с PKCE: открывается страница входа, а код
возвращается на `http://127.0.0.1:<порт>`, где его ждёт приложение (RFC 8252). Нужен точный
адрес — `redirect_uri = "http://localhost:8765/callback"`. Ещё есть `audience`,
`client_auth = "body"` (секрет в теле, а не в Basic) и `pkce = false`.

Cookie, которые ставят серверы, уходят обратно, как в браузере: на свой домен и путь, Secure —
только по HTTPS (и на этот компьютер), в том числе по ходу перенаправлений. У каждого
окружения своя банка cookie. `[options] cookies = false` — запрос без них.

Токены и cookie хранятся в папке данных приложения, не в коллекции. В CLI они живут, пока
идёт команда: вход в начале `run` годится для запросов после него.

`type = "digest"` с `username` и `password` — Digest (MD5 или SHA-256): запрос уходит без
авторизации, сервер отвечает 401 с вызовом, и запрос уходит ещё раз с ответом на него.

### Прокси и клиентские сертификаты

Прокси по умолчанию системный: `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, а если их нет — сетевые
настройки macOS. В приложении его можно сменить в «Настройках» на свой
(`proxy.corp:3128`, `http://логин:пароль@proxy:3128`, `socks5://proxy:1080`) или выключить, в
CLI — `-x адрес` и `--noproxy '*'`. Запросы на localhost и 127.0.0.1 всегда идут напрямую.
Автонастройка через PAC-скрипт не выполняется.

Клиентские сертификаты (mutual TLS) задаются у коллекции, по серверам:

```toml
# tsubamedo.toml
[[certificates]]
host = "api.bank.test"            # или "*.bank.test", "host:8443", "*"
cert = "certs/client.pem"         # PEM: ключ в нём же или в key = "…"
key = "certs/client.key"

[[certificates]]
host = "*.partner.test"
cert = "~/certs/partner.p12"      # .p12/.pfx, как их отдаёт Связка ключей
passphrase = "{{cert_password}}"  # значение — в tsubamedo.local.toml
```

.p12 и ключи под паролем читаются через системный `openssl`. В «Настройках» приложения
сертификаты добавляются кнопкой, и каждый сразу проверяется. В CLI — `--cert`, `--key`,
`--pass` для всех серверов.

### Проверки и значения из ответа

```toml
name = "Вход"
method = "POST"
url = "{{base_url}}/login"
checks = [
  'status == 200',
  '$.token exists',
]

[capture]
token = '$.token'          # другие запросы пишут просто {{token}}
```

Запрос, которому нужен `{{token}}`, а его ещё нет, сначала сам отправляет «Вход». При запуске
коллекции такие запросы идут первыми, даже если они в другой папке. Полученные значения
приложение помнит между запусками (в папке данных, не в коллекции).

Что проверять: `status`, `time` (мс), `size`, `header Имя`, `body` или JSONPath `$.путь`
(RFC 9535, с фильтрами `$.items[?@.price > 100]`); после него `count` — длина массива, строки
или число совпадений. Условия: `==`, `!=`, `<`, `<=`, `>`, `>=`, `contains`, `matches`
(регулярное выражение), `exists`, `empty`, `schema` (ниже), перед словами — `not`. Значение — JSON (`200`,
`"Кот"`, `true`, `[1, 2]`) или просто текст; `{{переменные}}` работают:

```text
status == 201
time < 500
header Content-Type contains json
$.items count > 0
$.user.name == "Котик"
$.id == {{order_id}}
$.error not exists
```

JSON Schema — условием `schema`: файлом или прямо в строке.

```text
$ schema schemas/order.json                     # весь ответ
$.items[*] schema schemas/order.json#/$defs/item # каждый элемент — частью файла
$.id schema {"type": "integer", "minimum": 1}
```

Файл ищется от папки запроса вверх до корня коллекции, поэтому общая папка `schemas/` в корне
годится всем запросам; `$ref` на соседние файлы работает. Схема без `$schema` считается draft
2020-12, поддерживаются и draft 4/6/7/2019-09; `format` — пометка, а не правило, как велит
стандарт. Каждое совпадение пути проверяется отдельно, в ответе — что и где не так:
`$.items[2].price: ожидалось число, а здесь строка`. Папки, где лежат только такие файлы, в
боковой панели не показываются. При импорте OpenAPI схемы ответов становятся файлами
`schemas/*.json`, а у запросов появляется `$ schema schemas/Pet.json` — проверка контракта сразу.

### Скрипты

Когда строк проверок мало — JavaScript до и после запроса. Он выполняется в ядре (QuickJS),
поэтому одинаково работает в приложении и в `tsubamedo run`:

```toml
[scripts]
before = '''
vars.set("ts", Date.now());          // {{ts}} подставится в этот же запрос
request.headers.set("X-Sign", crypto.hmac("sha256", vars.get("secret"), vars.render(request.body)));
'''
after = '''
const order = response.json();
vars.set("order_id", order.id);      // как [capture]: другие запросы отправят этот сами
test("заказ оплачен", () => expect(order.status).toBe("paid"));
console.log("товаров", order.items.length);
'''
```

- `vars` — `get`, `set`, `has`, `render(текст)`.
- `request` — `method`, `url`, `headers` и `query` (`get`, `set`, `has`, `remove`, `all`), `body`
  (текст JSON или просто текст; можно присвоить объект). До запроса — как в файле, с
  `{{переменными}}`, и его можно менять; после — то, что ушло, только для чтения.
- `response` (после) — `status`, `statusText`, `time`, `size`, `headers`, `text()`, `json()`.
- `test(имя, () => …)` и `expect(x)`: `toBe`, `toEqual`, `toContain`, `toMatch`, `toHaveLength`,
  `toHaveProperty`, `toBeGreaterThan`, `toBeLessThan`, `toBeTruthy`, `toBeDefined`… и `.not`.
  Тесты стоят рядом с проверками, в отчёте JUnit тоже.
- `console.log` — в журнал под ответом и в вывод CLI; `crypto.sha1/sha256/sha512/hmac`
  (hex или base64), `crypto.randomUUID()`, `btoa`/`atob` (строки UTF-8).

Песочница: без файлов, сети, модулей и таймеров; 5 секунд и 256 МБ на скрипт. Ошибка в
скрипте до запроса останавливает запрос, после — считается упавшей проверкой; строка ошибки
указана.

### Перенос из Insomnia, Postman, OpenAPI и HAR

`tsubamedo import ФАЙЛ` или ⇣ в боковой панели (⇧⌘I). Формат узнаётся по содержимому:

- **Insomnia** — экспорт версии 4 (JSON) и 5 (YAML, Insomnia 10 и новее): папки, запросы,
  окружения, авторизация папок, скрипты. Тег `{% response %}` («значение из ответа другого
  запроса») становится `[capture]` у того запроса и `{{переменной}}` там, где он стоял.
- **Postman** — коллекция v2.0/v2.1, окружение, глобальные переменные. Авторизация и
  скрипты коллекции и папок переходят в каждый запрос, переменные пути `:id` заполняются.
- **OpenAPI 3 и Swagger 2** (JSON или YAML) — запрос на каждую операцию в папке по тегу,
  тела-примеры из схем, авторизация из `securitySchemes`, проверка `status == 200` (или того
  кода успеха, что обещан) и `$ schema schemas/….json` по схеме ответа. Несколько серверов —
  несколько окружений с `base_url`.
- **HAR** из инструментов разработчика браузера — только обращения к API: картинки, стили,
  скрипты и проверки CORS пропускаются, повторы схлопываются.

Скрипты Postman и Insomnia работают как есть: `pm.environment.set`, `pm.test`,
`pm.expect(x).to.eql(…)`, `pm.response.to.have.status(201)`, `insomnia.*`, старые
`tests["…"]` и `postman.setEnvironmentVariable`, `CryptoJS.HmacSHA256`. Нет `pm.sendRequest`
(у скриптов нет сети) и `pm.cookies`. OAuth 2.0 переносится настройками: из Postman, Insomnia
и `securitySchemes` OpenAPI (client credentials, вход в браузере, пароль; implicit
становится входом в браузере с PKCE).

Импорт в открытую коллекцию ложится в новую папку; переменные, которые в коллекции уже есть,
не трогаются. Секреты (приватные окружения Insomnia, `secret` в Postman, всё, что называется
token, password, key…) пишутся в `*.local.toml`. Чего в TsubameDo нет — например, gRPC, —
перечисляется в конце, вместе с переменными, которые осталось задать.

Переменные подставляются в порядке силы: коллекция → её `.local` → окружение → его `.local` →
значения из ответов и скриптов → `--var` из командной строки. Встроенные: `{{$uuid}}`, `{{$timestamp}}`, `{{$timestampMs}}`,
`{{$isoTimestamp}}`, `{{$randomInt}}`, `{{$env.ИМЯ}}` (переменная окружения процесса — удобно для секретов в CI).

## Приложение

- Вкладки: ⌘T — черновик, ⌘W — закрыть, ⌘1…⌘9 — перейти, ⌘N — новый запрос в коллекции.
- `{{переменные}}` подсвечиваются везде, где их можно написать: незаданные — красным,
  при наведении видно значение и файл, откуда оно взято. После `{{` появляются подсказки.
- Команду curl (например, «Copy as cURL» из браузера) можно просто вставить в адрес — она
  станет запросом. Обратно — «Скопировать как curl».
- ⌘↵ — отправить, ⌘F — поиск в ответе или в теле запроса.
- Боковая панель повторяет папку коллекции: правый клик — переименовать, дублировать,
  перенести, удалить (в Корзину); запросы и папки можно перетаскивать.
- «История» в боковой панели: всё отправленное, с ответами до 1 МБ. Хранится в
  `~/Library/Application Support/app.tsubamedo.TsubameDo`, в git не попадает.
- Вкладка «Проверки» у запроса: проверки ответа (непонятная строка помечается сразу) и
  значения из ответа. У ответа — что прошло, что нет и что пришло вместо ожидаемого.
- Вкладка «Скрипты»: JavaScript до запроса и после ответа, с подсветкой и подсказками
  `vars.`, `request.`, `response.`, `expect(…).`.
- ▶ в боковой панели запускает всю коллекцию, «Запустить папку» в меню папки — одну папку.
  Панель запуска показывает план сразу и ход по мере ответов; в ней же — сколько запросов
  слать одновременно, сколько раз повторять упавшие и «Повторить упавшие» после запуска.
- Авторизация «OAuth 2.0»: поля, сохранённый токен (начало и конец, срок, есть ли refresh
  token), «Получить новый» и «Забыть». Заметки о получении токена — в «Журнале» ответа.
- «Настройки» в верхней панели: прокси (системный — с тем, что сейчас задано в системе; свой;
  без прокси) и клиентские сертификаты коллекции. В «Времени» у ответа — через какой прокси
  он шёл и какой сертификат ушёл серверу.
- «Cookie» в верхней панели — банка открытого окружения: что поставили серверы, удалить одну
  или все. «Очистить историю» удаляет и cookie, и токены.
- ⇣ (⇧⌘I) — импорт из Insomnia, Postman, OpenAPI или HAR: сначала видно, что придёт и что
  не перенесётся, потом — новой коллекцией или папкой в открытую.

## CLI

```bash
tsubamedo init my-api                         # новая коллекция с примером
tsubamedo send https://httpbin.org/get -i     # адрес, как curl
tsubamedo send orders/01-create -e stage      # запрос коллекции по имени
tsubamedo send orders/01-create.toml --var token=abc
tsubamedo send https://example.com/big.json -o big.json
tsubamedo run -e stage --fail                 # вся коллекция, код выхода для CI
tsubamedo run -e stage --junit report.xml     # и отчёт JUnit XML для GitLab, Jenkins, GitHub
tsubamedo run --filter orders --var token=$T  # только заказы; токен дан — вход не нужен
tsubamedo run -p 4 --retry 2                  # по 4 запроса сразу, упавшие — ещё до 2 раз
tsubamedo check                               # все ли переменные заданы во всех окружениях
tsubamedo import insomnia.json                # новая коллекция ./<имя> из Insomnia, Postman…
tsubamedo import openapi.yaml --to my-api     # в коллекцию my-api, в папку по имени API
```

`send` пишет статус и время по фазам (DNS, подключение, TLS, ожидание, загрузка) в stderr,
а тело — в stdout, поэтому его можно сразу передать в `jq`. В терминале JSON форматируется.
Для тестовых стендов с самоподписанным сертификатом есть `-k`, без cookie — `--no-cookies`; прокси —
`-x`/`--noproxy`, клиентский сертификат — `-E`/`--key`/`--pass`.
Вход в браузере для OAuth 2.0 открывает системный браузер (или команду из `$BROWSER`).

`run` отправляет запросы по порядку файлов, но каждый — после тех, чьи значения он берёт.
С `-p N` одновременно идут до N запросов: независимые — сразу, зависимые — когда готовы их
источники. Строки печатаются по мере ответов, а отчёт JUnit — в порядке коллекции. С
`--retry N` упавший запрос отправляется ещё раз (не тот, что не ушёл из-за незаданной
переменной: он упадёт так же).
Запрос считается упавшим, если ответа нет, не прошла проверка или не нашлось значение для
`[capture]`; с `--fail` — ещё и при статусе 400 и выше. `send` тоже выполняет проверки и
возвращает код 1, если какая-то не прошла.
