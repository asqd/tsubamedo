# Выпуск TsubameDo

Раздаём сами, без аккаунта Apple Developer и сертификата Microsoft: сборки подписаны ad hoc
(macOS) или не подписаны вовсе (Windows). Страница загрузки объясняет, как открыть их в первый
раз.

## Что выходит

| Система | Файл | Размер (0.1.0) |
|---|---|---|
| macOS 12+, Apple Silicon | `TsubameDo-<версия>-macos-apple-silicon.dmg` | 9,2 МБ |
| macOS 12+, Intel | `TsubameDo-<версия>-macos-intel.dmg` | 9,8 МБ |
| Windows 10, 11 x64 | `TsubameDo-<версия>-windows-x64-setup.exe` | — |
| Linux x86_64, ARM64 | `TsubameDo-<версия>-linux-<arch>.AppImage`, `tsubamedo_<версия>_<arch>.deb` | — |
| CLI | `tsubamedo-<версия>-<система>.tar.gz` (Windows — `.zip`) | 5 МБ |

Рядом с каждым — `.sha256`. Для Mac два DMG, а не один универсальный: универсальный весит 18 МБ,
вдвое больше, а цель — меньше 15.

## Порядок выпуска

1. `scripts/version.sh 0.2.0` — версия во всех файлах сразу (Cargo.toml, tauri.conf.json,
   package.json и их lock-файлы). Без аргумента скрипт печатает версию или падает, если файлы
   расходятся.
2. `make check`.
3. Коммит, тег и пуш: `git tag v0.2.0 && git push origin main v0.2.0`.
4. GitHub Actions (`release.yml`) соберёт всё на macOS, Windows и Linux (x86_64 и ARM64) и
   положит в черновик выпуска `v0.2.0`. Тег обязан совпадать с версией, иначе сборка упадёт.
5. Скачайте DMG из черновика и проверьте на Mac, как это сделает пользователь (ниже).
6. Опубликуйте черновик. Страница загрузки сама возьмёт новые ссылки, версию и размеры из
   GitHub API — править её не нужно.

`make release` собирает то же для своей системы локально, в `build/release`.

## Первый запуск без подписи

- **macOS 15 и новее**: «не удалось проверить» → «Готово», затем «Системные настройки» →
  «Конфиденциальность и безопасность» → «Всё равно открыть» и пароль.
- **macOS 12–14**: правой кнопкой по приложению → «Открыть» → «Открыть».
- **В Терминале**: `xattr -dr com.apple.quarantine /Applications/TsubameDo.app`.
- **CLI**, скачанный через `curl`, карантинной метки не получает и запускается сразу.
- **Windows**: SmartScreen → «Подробнее» → «Выполнить в любом случае».

Подпись ad hoc обязательна на Apple Silicon (без неё код не запустится) и уже проверена: обе
сборки проходят `codesign --verify --deep --strict`.

## Ручная проверка перед публикацией

- DMG монтируется, в нём `TsubameDo.app` и ярлык «Программы».
- `lipo -archs TsubameDo.app/Contents/MacOS/tsubamedo-app` — `arm64` и `x86_64` в своих DMG.
- Приложение открывается (Intel — и через Rosetta), отправляет запрос, история пишется.
- `tsubamedo --version` из архива CLI печатает новую версию.
- Суммы `.sha256` совпадают со скачанными файлами.

## Страница загрузки

`site/` — статическая страница; `pages.yml` выкладывает её на GitHub Pages
(`<владелец>.github.io/<репозиторий>/`) при изменении на `main`. Один раз в настройках
репозитория: Settings → Pages → Source: GitHub Actions.

Снимки экрана (`site/assets/shots`, светлые и тёмные; английские — в `site/assets/shots/en`
для `site/en/`) снимаются заново командой `make screens` при запущенном `make bridge`:
демо-коллекции `design/screens/shop` и `shop-en` и их серверы (`design/screens/servers.py`, под
`/en` — английские данные), прокликанные в WebKit (`design/screenshot.swift`) на русском и на
английском. Чужие коллекции в кадр не попадают.

## CI

Минуты Actions тратятся экономно: каждый запуск — только то, чего не видно на Mac.

- `ci.yml` — на пуш в main и на pull request, кроме правок документации, сайта и дизайна:
  тесты, clippy и проверка типов на Linux, сборка CLI на Windows. macOS проверяет `make check`
  перед коммитом.
- `release.yml` — установщики: на тег — в черновик выпуска; вручную (Actions → Release → Run
  workflow) — только сборка, после изменения упаковки. Сам по себе не запускается: раннер macOS
  самый дорогой.
- `pages.yml` — страница, когда меняется `site/`.
